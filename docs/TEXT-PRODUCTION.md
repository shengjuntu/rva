# 文本驱动新闻视频 · v0.9.0

## 工作流

1. 新建项目，粘贴正文或导入 UTF-8 TXT / Markdown 正文。Markdown 按原文处理，不自动去掉标记。
2. 上传图片/视频，或通过“导入素材目录”选择本机目录。浏览器读取目录文件并上传，服务端不会扫描任意宿主路径。
3. 保存正文与对齐表。App 按句末标点/换行分段，超长段落按220字切分；原文字符与顺序保留。每段生成稳定 segmentId 和一个画面镜头，初始时长按字数估计。
4. 直接逐段选图片、视频或文字卡；也可连接 RunDesk，点击“让 RunDesk 安排素材”。已连接时直接发送制作要求；未连接时保留要求，连接后发送。
5. 使用已配置 IndexTTS 生成配音，试听并采用。采用后按实测段落音频时长调整画面及句级字幕。
6. 生成初稿、预览并通过对话或对齐表调整。初稿可以使用已绑定音频但未经人工核对的字幕；过期字幕/配音绑定仍会阻止渲染。
7. 核对配音、正文与字幕，按需要重新渲染，然后确认当前成片为终稿。终稿指向一个已完成、内容完全一致的渲染结果，不自动发布。

## App + RunDesk

App 保存正文、段落、素材选择、音轨、字幕、渲染快照及终稿。RunDesk 管理 Codex 会话、执行与现有审批。制作能力继续使用本 App 的 HyperFrames + GSAP + FFmpeg 与已有 IndexTTS；没有引入 OpenMontage 的代码、服务、Python编排器或云模型依赖。

参考 OpenMontage 的指令驱动流程、工具契约、持久产物与阶段检查，收敛为初稿、调整、终稿三个阶段。这里借鉴架构思路，未复制第三方源码。

## MCP

- `video_production_text(projectId, revision, text)`：保存完整制作正文。完全相同段落复用素材、镜头ID和时长；新增/改写段落产生新ID。旧配音保留可查看，字幕绑定会检测正文/结构变化。
- `video_asset_inspect(projectId, assetId)`：实际素材PNG预览，最长边640像素。视频当前只返回第一帧，不等同于完整视频分析；需要FFmpeg。
- `video_project_update`：保留正文段落的 segmentId、text 和顺序，调整title、assetId、duration及音轨。正文改写必须用正文工具。
- `video_render_start(projectId, kind="draft")`：生成初稿预览；省略kind沿用旧版严格字幕校验。
- `video_production_stage(projectId, revision, stage, renderId)`：draft / adjustment / final。final要求当前内容哈希与指定已完成渲染相同，并核对启用的字幕。

所有正文/阶段写入有revision检查。后续画面、配音、字幕内容变化会让终稿自动回到调整；旧成片继续保留。

## 简化与当前边界

- 本版一段正文对应一个素材或文字卡。暂不支持一段多素材、多画面切点或自由轨道编辑。
- 语义选图由有视觉能力的Codex通过素材预览完成；App提供对齐数据与操作，不内置图文向量模型，也不假称文件名匹配就是语义对齐。
- 配音字幕为实测句段时序；不是逐字强制对齐。
- 修改后的完整视频仍全量渲染；未实现局部镜头渲染缓存。
- 素材目录导入支持图片、视频及音频；正文通过独立入口导入。未知文件跳过。
- 无需改RunDesk服务协议或news2douyin交接包。已有项目需点击“升级项目工具至v0.9.0”刷新实例Skill/MCP。
- 旧项目不强制迁移；点击保存正文后进入文本驱动模式。升级前备份完整data目录。
