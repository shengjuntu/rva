# 配音与字幕时间轴 · v0.4.0

字幕拥有独立的绝对时间轴，不随画面镜头切分。SRT 时间按毫秒保存，实际成片显示受 30 fps 帧边界约束。画面文字和字幕分别显示，原始新闻成片继续独立保留。

## 采用新闻原片

1. 导入已审核脚本包，再接收相同稿件的成片 ZIP。
2. 点击“采用原片配音与字幕”，确认替换当前配音与字幕、按配音总长调整镜头。
3. WAV 会复制到当前工程素材库；字幕保留原 SRT 的起止时间。镜头文字、标题、素材、背景音乐保留；原稿和原片不变。
4. 镜头总长取配音时长和字幕末尾的较大值，向上取整到 30 fps 帧边界，原镜头时长按比例缩放。**视觉切点仍是估算，未逐镜头进行语音对齐。**
5. 试听、检查切点并生成视频。新成片有自己的工程快照和 SRT 下载，不会覆盖原新闻成片。

当前分镜正文必须与原字幕正文一致（忽略空白），改写过的口播不能直接采用旧配音。缩放后任一镜头不足 1 秒或超过 60 秒会拒绝，先合并或拆分镜头；总长仍限 600 秒。已配置背景音乐的起点如果超出缩短后的成片，也会拒绝。每次采用生成新的素材副本，不删除旧素材。

## 使用自己准备的 WAV / SRT

1. 上传音频，在“配音”选择素材并设置音量、视频起点和截取起点，调整镜头总长。
2. 导入 UTF-8 SRT 或直接编辑；时间从**视频起点**计算，不是音频源文件起点。
3. 保存字幕草稿。拖动“已保存字幕预览”定位配音播放器，播放时显示对应字幕。试听仍使用源配音，不包含背景音乐与混音增益。
4. 逐段听过当前配音，核对文字与时间后点击“已试听核对当前字幕”。如果正文变化需要新语音，先准备新音频，再核对。系统不会因确认按钮生成新语音；v0.5.0 可用单独的自动配音任务生成并采用，见 [SPEECH.md](SPEECH.md)。
5. 字幕状态可渲染时生成视频。也可以明确取消“在成片中显示字幕”并保存，以输出不含字幕的版本。

SRT 需从序号 1 连续递增，1–300 段、每段 1–120 字、最多 3 行，文件最大 128 KiB；时间非负、有序、不重叠，支持逗号或点作为毫秒分隔符。允许字幕间隙和多行正文；格式标签按普通文字显示。字幕必须在分镜总长内；核对时还检查配音播放区间、实际可解码音频和完整播放时长。配音尾部与视频时长允许约一帧误差，字幕结束与配音尾部允许 150 ms 容差，沿用新闻包时长容差。超长字幕需手动拆段并核对时间，不会自动猜测新时间。

## 状态与绑定

| 状态 | 含义与操作 |
| --- | --- |
| ready | 已绑定当前正文、配音文件及起点，可渲染 |
| unreviewed | 字幕文字或时间被修改，需要重新试听核对 |
| stale | 正文、配音选择、起点、截取或可播放时长已变化；按提示修正并核对 |
| disabled | 用户关闭字幕，不参与渲染 |

旧绑定记录正文哈希（忽略空白）；v0.5 新绑定还记录镜头 ID/顺序及保留词间空格差异的正文哈希。另外记录音频素材 ID、文件 SHA-256、实际音频时长、视频起点与源截取起点。配音音量调到 0 也会阻止启用字幕的渲染。改标题、画面素材、背景音乐或分镜说明不影响配音绑定；只调视觉切点，只要完整配音和字幕仍在总长内，也不要求重复核对。恢复为已绑定的正文/音轨参数后可重新变为 ready。

原片采用记录 `news_package`，人工核对记录 `manual_review`。v0.5.0 的自动配音采用记录 `synthesized_sentence_durations`，按合成音频的实测分句时间生成字幕。以上记录都**不是语音转写验证**，不能证明音频实际说了哪些词，也不代表新闻事实审核。MCP 的人工核对参数依赖用户明确确认；Skill 不允许 Agent 自行声称已试听。

已启用字幕处于 stale/unreviewed 时，开始渲染返回 409。渲染快照会再次核对复制后的音频哈希；素材被外部改写会导致任务失败，无法下载未通过检查的 MP4。普通项目 PUT 不能改写字幕或其绑定。

## HTTP / MCP

所有接口沿用本机 Host、同源及令牌校验；写入必须带当前 revision。

| 接口 | 参数与行为 |
| --- | --- |
| POST /api/projects/{id}/news/audio | `{revision}`；替换配音/字幕并缩放镜头，返回新 Project |
| PUT /api/projects/{id}/subtitles | `{revision,srt,enabled,reviewed}`；保存草稿或记录人工核对，返回新 Project |
| GET /api/projects/{id}/subtitles.srt | 下载当前可编辑字幕，包括尚未核对的草稿 |
| GET /api/projects/{id}/renders/{rid}/subtitles.srt | 下载该次渲染快照字幕，内容不随后续编辑变化 |

`reviewed=false` 保存新文字/时间为待核对；规范化后内容完全相同时保留已有绑定。`enabled=false,srt=""` 明确删除字幕轨；`enabled=false` 加原 SRT 仅关闭显示。API 可保存超出当前视频时长的草稿以便后续调整，但核对和渲染会拒绝，所有字幕始终受 600 秒上限约束。

MCP 新增 `video_news_audio_adopt(projectId,revision)`、`video_subtitles_update(projectId,revision,srt,enabled,reviewed)`；读取使用既有 `video_project_get`，v0.4 共七个工具，v0.5 加配音任务后共 10 个。reviewed=true 只能用于用户明确表示已核对的那份配音和字幕。旧客户端提交 project.subtitles 会被忽略。

字幕核对在锁外探测音频，发布前再次比较 revision；失败不覆盖新编辑。发布保留同一期间更新的渲染/会话元数据。采用失败会移除本次新增 WAV；突然断电可能残留未引用副本或 subtitle-review-* 临时目录，不会加载为工程。项目 JSON 与所有素材仍需一并备份。

## 验收复现

先构建 bin/video-app，安装 runtime 依赖并准备测试浏览器和中文字体。Playwright 仅为开发验收依赖，普通使用不需要它。

```bash
PLAYWRIGHT_MODULE=/absolute/path/to/playwright \
HYPERFRAMES_BROWSER_PATH=/absolute/path/to/chrome \
VIDEO_FONT=/absolute/path/to/chinese-font.otf \
VIDEO_TEST_OUTPUT=/tmp/subtitle-validation \
node scripts/smoke-subtitles.cjs
```

脚本启动隔离的本机 APP，在浏览器中导入配套新闻包、采用 WAV/SRT、生成真实视频、检查音视频流与字幕快照、编辑失效和并发草稿保护。默认端口 3342，可用 VIDEO_TEST_PORT 修改。不会调用模型；结束会停止测试服务。
