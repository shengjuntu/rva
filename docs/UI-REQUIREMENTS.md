# RunDesk Video App UI 优化需求

日期：2026-10-28

状态：讨论总结与后续改造依据，尚未实现或验收。

代码基线：v0.27.0（`8e4f283`）。

## 1. 核心方向

用户不该感知 Agent 的存在，日常操作只需要：**写文案 → 点“开始制作” → 等片**。出片后，需要调整时再进入精修页。

Video App 管项目、输入、素材、作品版本、审阅和导出；RunDesk 管执行环境、Skills/MCP、运行轨迹和深入调试。页面可以按使用目的拆分，但不把 Codex 的制作方式限定成固定工作流。Codex 仍可根据实际结果反复取材、生成、检查和重做。

正文仍是内容依据，图片、视频、动画和声音服从文字。此次 UI 改造不增加固定分镜模板，也不改变自由内容与剪辑 DSL 的分工。

## 2. 当前问题

以下记录用户测试反馈，具体故障原因需要在实现时复现定位：

1. **制作入口混乱**：中栏“确认原制作提交”和右栏对话发送同时存在，用户无法判断哪个操作真正启动制作；测试体验是中栏只保存配置，还要在对话中发送“开始制作”。
2. **新旧结果混淆**：制作中仍展示历史版本，容易把旧片误认成此次的新片。
3. **输入与指令分裂**：正文编辑和对话分居中、右两栏，操作路径断裂。
4. **项目缺少筛选**：左侧一直列项目，数量增加后难以查找。

基线代码中，`startProduction()` 已包含保存输入和派发制作请求的逻辑；“确认原制作提交”用于未确认请求的恢复。此记录不将问题直接归因为“缺少派发代码”。后续需同时验证成功、失败、回执丢失和刷新恢复的实际行为，消除用户必须再发一句“开始制作”的体验。

## 3. 页面 A：制作页

用于首次出片，以简单为主。

### 3.1 空闲时

- 左栏显示共用的精简项目列表。
- 主区提供正文输入、正文导入、图片/视频等素材挂载，以及可选的制作要求。
- 只保留一个醒目的制作主按钮：**开始制作**。
- 点击一次即可保存本次输入并自动启动制作，不要求用户打开对话或再发启动消息。
- 不显示对话栏，不显示历史版本列表。

### 3.2 制作中

- 正文、要求及素材输入区自动收起，保留已提交内容和未提交草稿。
- 主区显示进度条、当前制作阶段、关键日志摘要，以及有真实结果时的当前帧预览。
- 产品文案优先使用“制作动态”“正在配音”“正在合成”等表达，不要求用户理解 Agent、工具调用或会话协议。
- 隐藏历史成片和历史版本列表，不能用旧片或旧帧冒充本次进度。
- 制作页不放“停止制作”按钮；停止入口仅在精修页。

进度必须有数据依据。有可信百分比时显示实际进度；没有时显示不定进度条和真实阶段，不按时间估算或编造完成百分比。尚无本次帧预览时，只显示等待说明。

### 3.3 完成后

- 高亮展示本次任务产出的完整新片，并提供下载/导出。
- 提供明确入口：**不满意？去精修页调整**。
- 制作页仍不展示历史版本列表或对话栏。
- 中间预览、局部片段和单个工具任务完成，不能直接作为“出片完成”。

## 4. 页面 B：精修页

用于出片后的审阅和迭代，需要时才进入。

- 播放当前片子，明确当前版本。
- 提供逐镜头、逐帧定位及调整入口。
- 在此页通过对话提出修改，例如“第二节重做，其他部分保留”。
- 展示历史版本，支持多版本对比和确认终稿。
- 提供下载/导出。
- 有可停止的制作任务时，显示“停止制作”；停止中的状态与实际停止结果分开显示。

对话修改仍交由 RunDesk 执行。Video App 提供视频、定位、版本和简要制作动态；详细轨迹、工具参数、模型调试仍在 RunDesk。

“逐镜头/逐帧调整”已经纳入目标，但本轮总结不把它等同于完整手动剪辑器。定位控件、时间线编辑能力及分期范围见第 9 节待讨论项。

## 5. 共用左栏：快速切换项目

- 顶部为搜索框，按项目名过滤。
- 默认只显示最近打开的 **5 个**项目，按打开时间排序。
- 项目前显示状态色点，同时提供文字或可访问名称，不只靠颜色区分。
- 已定义的状态含义如下。

| 标记 | 含义 |
| --- | --- |
| 🟢 | 制作中 |
| ⚪ | 已出片 |
| ✅ | 已确认终稿 |

- 底部设置“查看全部 / 归档”折叠入口，供访问较早项目和归档项目。
- 重命名、删除、归档及批量管理放设置页，侧栏只负责快速切换。
- 两页打开同一项目时，使用同一项目身份、制作环境绑定和版本数据。

搜索范围、归档语义及其他状态的表达见第 9 节，尚未定案。

## 6. 制作页状态切换

| 状态 | 主区显示 | 不能发生的情况 |
| --- | --- | --- |
| 空闲 | 正文、素材、可选要求及“开始制作” | 要求用户再去对话框启动 |
| 提交中 | 保存/发起状态，防止重复操作 | 仅保存成功就宣称“制作中” |
| 制作中 | 进度、真实阶段、本次帧预览及关键日志 | 混入旧片、旧帧或历史版本列表 |
| 完成 | 本次完整新片、导出及精修入口 | 把局部预览当完整成片 |
| 失败/中断 | 真实结果说明，保留输入与已有产物 | 显示成功，或把旧片顶替为新片 |
| 请求结果待确认 | 明确说明正在核对原请求 | 自动另发一个制作任务 |

“提交中”“待确认”“失败/中断”是必要的异常展示状态，不是要求用户逐步点击的制作流程。

## 7. 一键制作与恢复的验收约束

1. **单一入口**：一次点击完成保存与启动；正文或要求保存失败时，不启动基于旧内容的制作。
2. **输入一致**：启动任务使用本次已保存的正文、要求和素材依据；不能把“已保存”与“已派发”混为一谈。
3. **避免重复**：重复点击、超时重试、刷新恢复都复用原请求身份。回执未知时先核对，不新建另一份任务。
4. **项目隔离**：切换项目后，迟到的任务状态、日志、帧预览和成片不能覆盖当前项目。
5. **结果归属**：制作页的新片和帧预览必须能够归属到本次制作。当前归属信息不足时，应补齐契约，不能只取“最新已完成渲染”猜测。
6. **历史保留**：制作页隐藏历史，不删除历史；精修页仍可查看真实版本和导出。
7. **刷新恢复**：重新打开制作中的项目能够恢复当前状态，不重发任务；未提交正文和对话草稿按项目保留。
8. **失败可恢复**：保存、派发、状态查询和实际制作失败需要区分。失败或取消不清空用户正文和素材。
9. **环境兼容**：保留 v0.27.0 的新建项目环境搜索与选择；页面拆分不迁移旧项目的环境、工作区或会话。
10. **版本一致**：精修定位、对话调整、对比和终稿操作均绑定明确版本；不能对旧片定位后静默修改另一个版本。

## 8. 验收场景

| 场景 | 预期 |
| --- | --- |
| 新项目填写正文并挂素材，点“开始制作” | 自动保存并启动，无需发送聊天消息 |
| 已有成片的项目发起新制作 | 进入制作中状态，制作页不展示旧版本 |
| 请求已经发出，但浏览器没有收到回执 | 恢复或核对同一请求，不重复派发 |
| 制作中刷新页面或切换项目再回来 | 恢复实际制作状态，不再次启动 |
| 某个配音或渲染步骤暂时没有百分比/帧预览 | 显示真实阶段和等待状态 |
| 任务失败或中断 | 明确展示结果，保留输入，不显示假新片 |
| 新片完成 | 展示本次完整成片和导出，提供精修入口 |
| 进入精修并用文字提出修改 | 启动调整，完成后形成可区分的新版本 |
| 从精修查看旧版本 | 版本身份明确，可播放和导出，不混淆终稿 |
| 项目超过 5 个 | 默认显示最近打开的 5 个，其余从搜索/全部入口访问 |
| 打开已有项目和已确认终稿 | 数据、素材、环境绑定、历史与终稿保持有效 |

## 9. 实现前仍需讨论的边界

以下是未定项，不代表已批准增加功能，也不阻碍先按第 3—8 节实现明确的核心行为。

- **制作中如何进入精修页停止任务**：停止只在精修页，但精修又以出片后进入为主。需确定制作中是否保留“进入精修”入口，以及无成片时该页如何呈现。
- **逐镜头/逐帧的调整范围**：是选择镜头或时间点后用文字修改，还是包含直接编辑时间线？镜头依据采用哪份真实工程/审阅数据，不能凭播放器时间猜测。
- **多版本对比方式**：先切换播放、并排播放，还是同步对比；尚未指定。
- **搜索范围**：检索所有未归档项目还是仅最近项目；归档项目是否包含在普通搜索中。
- **最近打开时间**：按当前浏览器保存还是按用户在服务端保存，以及跨设备如何处理。
- **其他项目状态**：未制作、失败、取消、待确认、正在修改已有终稿时如何显示；已有的三种色点不足以覆盖这些情况。
- **归档及批量管理**：当前数据模型和 API 能否支持；归档是否只是可恢复隐藏，以及是否允许归档运行中的项目，需单独定义。
- **失败后的重试入口**：如何让用户重试而不恢复复杂控制台；新任务重试与原请求回执核对必须区分。

## 10. 文档与发布边界

本文件记录下一轮 UI 目标，不表示 v0.27.0 已提供两页布局、项目归档、逐帧编辑或多版本对比。README 的当前使用说明及历史验证记录仍描述已发布版本。

开始实现时，先复现第 2 节反馈、明确第 9 节影响实现的边界，再按上述场景验收。页面改动可分批交付；每次发布必须说明实际完成范围，不能只换按钮文案就宣称一键制作或新旧结果隔离已完成。
